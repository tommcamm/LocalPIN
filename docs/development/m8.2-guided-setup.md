Date: 2026-10-17. Status: implemented with local source, terminal and package

## Resulting behavior

The RPM adds `localpin` as an alias for the existing `localpinctl` executable.
The no-argument terminal menu offers setup, diagnostics and credential
management. `localpin setup` guides the current account through preparation,
explicit backend selection, enrollment, bounded trials, actual desktop tests,
console recovery rehearsal, re-enrollment and final activation. It pauses for
the existing offline persistent-accounting prerequisite rather than copying
live native counters. Existing low-level commands and status/doctor JSON
schema 1 remain available.

[ADR 0019](../adr/0019-guided-setup-orchestration.md) defines the fixed sudo
boundary. The helper checks the sole account scope under its transaction lock.
Final test confirmations bind to an opaque reference for the exact live trial;
a replacement trial cannot reuse earlier confirmations. Resumed onboarding
also checks the broker's account/session/enrollment readiness before trial or
activation. A helper pointer report alone cannot establish native account
continuity. Healthy active integration is retained across reboots and ordinary
credential changes.

## PR #8 independent agent review and fixes

Three fresh-context agent reviews examined commit `e764c18`: the Rust CLI and
terminal flow, privileged helper/transaction boundaries, and packaging,
dependencies and documentation. The packaging pass found no additional
actionable defect. Two confirmed P2 findings were fixed on the same PR:

- An active installation without enrollment returned from setup immediately,
  while the menu's change/migrate actions required enrollment. Setup now offers
  explicit fresh enrollment, preserves active integration, and requires a fresh
  active/enrolled report and broker readiness before reporting success.
- Setup's scope check held the integration lock, but native account mutations
  used a separate registry lock. A synthetic interleaving showed another UID
  being provisioned after that check and then revoked by setup. Native account
  mutations now acquire the integration lock first. Fixed helper children adopt
  its verified inherited descriptor; other account administrators refuse Busy
  before modifying gate, registry, policy or credentials. Descriptor ownership,
  modes, inode identity and close-on-exec behavior are checked, and a child
  cannot release its parent's lock by dropping a duplicate.
