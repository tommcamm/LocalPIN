# M8.2 guided CLI and setup validation

Date: 2026-10-17. Status: implemented with local source, terminal and package
validation; installed Fedora KDE onboarding acceptance remains outstanding.

## Resulting behavior

The RPM adds `localpin` as an alias for the existing `localpinctl` executable.
The no-argument terminal menu offers setup, diagnostics and credential
management. `localpin setup` guides the current account through preparation,
explicit backend selection, enrollment, bounded trials, actual desktop tests,
console recovery rehearsal, re-enrollment and final activation. It pauses for
the existing offline persistent-accounting prerequisite rather than copying
live native counters. Existing low-level commands and status/doctor JSON
schema 1 remain available.

[ADR 0019](../adr/0019-guided-setup-orchestration.md) defines the fixed sudo
boundary. The helper checks the sole account scope under its transaction lock.
Final test confirmations bind to an opaque reference for the exact live trial;
a replacement trial cannot reuse earlier confirmations. Resumed onboarding
also checks the broker's account/session/enrollment readiness before trial or
activation. A helper pointer report alone cannot establish native account
continuity. Healthy active integration is retained across reboots and ordinary
credential changes.

does not establish installed PAM behavior. No host PAM configuration, real
credential state or physical TPM was used as a test fixture.

CLI coverage includes preparation/enrollment/trial resume, recovery handoff,
active no-op, explicit TPM/software selection without downgrade, account and
service unavailability, canceled/declined steps, trial replacement/expiry,
attestation/activation refusal and no automatic mutation retry. PTY tests cover
hidden secrets, bounded visible choices, control-byte rejection, terminal
restoration, job control, colors, `NO_COLOR`, `TERM=dumb` and redirected output.
Helper tests cover read-only preflight, unsafe/unknown state, both manifest and
registry scope, exact trial/enrollment references and mutation preconditions.

## Outstanding installed acceptance

The earlier private M8.1 disposable clone and temporary access were removed
after that matrix. No new installed wizard run was performed for this change.
The following remain explicit acceptance work in a fresh independently cloned
Fedora KDE 44 VM with SELinux enforcing and a private TPM emulator:

- Clean RPM installation remains inactive; both executable names work and the
  owner can complete fixed sudo steps from the foreground KDE terminal.
- Accounting prerequisite handoff, actual PIN/password/failure tests, genuine
  administrator-console recovery, fresh enrollment and final activation.
- Cancellation, service failure, reboot/trial expiry and resume at each stage.
- Compatible RPM upgrade preserves enrollment and prior activation; setup
  recognizes the resulting state without repeating preparation.

build and operator attestations do not supply those observations. Independent
