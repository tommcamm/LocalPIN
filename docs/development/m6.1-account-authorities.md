# M6.1 production account lifecycle and eligibility

Date: 2026-10-17. Status: M6.1 complete for ADR 0012's explicitly defined
Fedora 44 KDE x86_64 Btrfs appliance domain.
M7 unlock integration and M8 packaging/confinement have not started.

## Implemented authority and support domain

[ADR 0012](../adr/0012-immutable-appliance-account-authority.md) chooses an
explicitly provisioned Fedora 44 x86_64 Btrfs appliance domain. Ordinary Fedora
accounts are not adopted. Kernel immutable flags protect account/PAM files and
their containing directories. A kernel read-lease barrier additionally proves
that writers opened before sealing, including shared writable mappings, have
drained. The protected, versioned `LPACCT02` registry records fresh opaque
incarnations and the enforced input snapshot. Earlier experimental format 01
is refused; root provisioning always creates a fresh disabled incarnation.

The authority retains a shared global lease through each enrollment/verification
storage guard and actual response delivery. Root `begin-mutation` obtains the
exclusive lease and durably revokes every managed incarnation before clearing
immutable flags. The native shadow-utils password-database lock also excludes
administration already in progress. Standard account tools and AccountsService
work only in the revoked domain. Every reseal, including rename or UID changes,
creates fresh identities and requires re-enrollment. There is no continuity
claim from matching UID, name or home.

Privileged `seal`/`recover` require the broker stopped, quarantine old or partial
UID state, initialize disabled generation-one baselines and publish the registry
only after their durability and the final writer/flag/snapshot checks. Missing
or corrupt lifecycle/storage state cannot be repaired through own-user requests.
Existing-user operations now require the permanent UID lock to exist. Root
quarantine can move corrupt metadata without following or normalizing it.
Quarantine history is bounded at sixteen entries per UID.

`SystemAuthorities` now uses this lifecycle authority and a separate bounded
password-free eligibility child. The child pins the measured Fedora policy graph
and native PAM binaries, requires local files-only NSS, unique local identity,
the supported UID/name/home/bash domain, strict SHA512-crypt or default yescrypt,
usable unlocked passwords and conservative account/password aging. Forced
changes, nologin, unsupported restrictions/policy and unknown state deny PIN.
Its explicit faillock preauth and account checks never receive a candidate or
permit a conversation, and exclude all counter reset/failure-write hooks.
Tally bytes and inode/ownership/mode/timestamps must remain unchanged.

The policy pool has four live/retired slots, one per UID, and retains capacity
until reaping. Original boot-time deadlines, peer/session binding, cancellation,
KDF budget, generation fences and delivery locks remain in force. The policy
subdeadline reserves 100 ms for an unavailable response: native PAM can retain
its original failure delay during lockout. Such a bounded refusal may report
`eligibility-unavailable`. The original password route keeps its own delay and
accounting. Doctor/status distinguish unsupported accounts, unavailable lifecycle
and unavailable eligibility without exposing identities or shadow data.

See [account administration](../account-administration.md) for the exact mutation,
recovery and compatibility procedures.

SELinux **Enforcing**, dedicated test accounts, an actual Plasma/Wayland desktop,
native logind/user-manager routing and the installed production broker/helpers.
It has no TPM, host filesystem shares or hardware passthrough. The original VM
remains off. Test passwords and PINs stay in guest-root-private storage and are
absent from exported evidence. No everyday-host account, PAM, enrollment or

## Findings fixed during implementation and review

The actual Btrfs bypass test disproved an immutable-only sealing design:
`pwrite` through an older writable descriptor still succeeded. The domain was
revoked and the clone recovered; this was never accepted as continuity evidence.
The revised kernel read-lease barrier refuses sealing while an earlier writer
or shared writable mapping exists. Registry format 02 explicitly excludes
registries created without that proof. Separate native tests and independent
review cover acquisition, lease loss and the final publication callback.

Independent development review also found and corrected missing UID-lock
recreation, partially published faillock metadata and cancellation of policy
children. Tally provisioning now uses an unnamed temporary inode, completes
ownership/mode/fsync before no-overwrite link publication, then syncs the directory.
Existing accounting is never overwritten. A socket monitor now detects pending
cancellation and disconnect while a native policy child is running. A parallel
test's EOF assertion now explicitly shuts down the socket before closing it.

Three separate agents reviewed lifecycle/storage, eligibility/native PAM and
broker/CLI integration; fixes received separate re-review. This is AI-assisted
development review, not M9's independent human/specialist release review.

## Limits and retained gates

The supported domain freezes global account and policy files, including `/etc`
directory entries. Account/password/policy administration and affected package
updates require global revocation and fresh enrollment. This is an appliance
restriction, not general-purpose Fedora laptop lifecycle support. Root flag
clearing, trusted registry substitution, raw filesystem/mount/snapshot rollback
and kernel compromise remain outside the specification's root threat boundary.

Fedora's default faillock directory is volatile. Missing tallies after reboot
make PIN unavailable; only explicit privileged fresh provisioning may establish
a missing empty baseline. Existing canonical accounting is retained, and unknown
or noncanonical accounting is refused. The implementation does not claim
transparent availability across reboot with lost authoritative tally state.

The enforcing component run uses administrative service domains. It does not
certify the installed broker/password-worker sandbox, RPM/SELinux lifecycle,
stock KDE PIN success/fallback, physical TPM operation, hardware power-loss
durability, hosted CI or M9 review. Those retain their separate M7/M8/M9 gates.
The supplied M5 service restrictions are not presented as an installed M6.1 PAM
worker confinement solution. No KDE unlock adapter is installed by this work.
