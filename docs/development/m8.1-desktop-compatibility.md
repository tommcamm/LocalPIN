# M8.1: Ordinary Fedora KDE account and update compatibility

Date: 2026-10-17. M8.1 replaces the historical immutable-appliance architecture.
M9 independent review, physical TPM/hardware and release gates remain open.

## Delivered

[ADR 0017](../adr/0017-shadow-record-account-authority.md) binds a root shadow-record
marker to an independent random 128-bit incarnation. Native OFD account locks
remain held through authorization delivery. Ordinary password/aging changes,
service-account additions and package maintenance no longer require freezing
`/etc` or resealing every account. Deletion removes the marker, including when
UID, name, retained home and imported password hash are reused. Missing or
ambiguous authority stays unavailable. The native-tool test caught glibc's
32-bit shadow-field parser limit; generation and every validator use
1–4294967294 while keeping the registry's reserved u64 wire slot.

[ADR 0018](../adr/0018-kde-native-update-compatibility.md) corrects KDE's auth-only
native accounting with dedicated password/fingerprint substacks. Sensor/service
unavailability adds no manufactured failure; genuine rejection is counted;
password/biometric success reaches native `authsucc`; PIN success bypasses that
reset. Native preauth denies locked accounts. A noninteractive guard selects the
original authselect stack if an unsupported restriction is added or the guard
module is unavailable. Adding a second factor cannot silently turn into direct
password-only authentication. Both KDE service suffixes and unrelated formatting
are retained, with owned backup/recovery and removal reference checks.
The policy guard also rejects unknown or noncanonical PAM types and unsupported
raw syntax before normalization, including uppercase types, Unicode/control
whitespace and ambiguous comment/continuation syntax. This prevents a malformed
or newly restricted native policy from being mistaken for the reviewed graph.

Runtime dependencies follow Fedora's stable Linux-PAM ABI with safe root-owned
native files and per-operation consistency checks. Stock `files systemd` NSS,
including group merge actions, is supported. Exact reference-library hashes and
filesystem inode snapshots no longer determine account continuity. Compatible
LocalPIN RPM upgrades preserve registry, credentials and throttles, restore prior
activation after validation, and retain durable replay after interruption.

## Executed evidence

[Repository checks](../../experiments/m81/results/repository-checks.json) record
319 Rust tests passing, 10 explicit ignores, full formatting/clippy/release and
dependency-policy checks, 72 integration tests and eight packaging tests. The
native enrollment suite, 77 production PAM adapter checks and 14 KDE accounting
checks passed. Native accounting probes include unavailable/rejected/successful
fingerprint responses, password success/failure, locked accounts, unsupported
added factors and the native disabled-fingerprint graph. Physical sensor
acceptance remains separate.

[Native account tools](../../experiments/m81/results/account-tools.json) ran in
private synthetic mount/PID namespaces inside an independently guarded Fedora
KDE 44 x86_64 KVM clone with SELinux enforcing. Actual passwd, chage, usermod,
chpasswd/PAM, newusers and systemd-sysusers preserved the marker as expected.
Userdel and identical recreation lost it. Native writers waited for OFD readers,
and native glibc writers excluded new readers. AccountsService's package and
native-tool dispatch were inspected; a GUI/DBus administration path was not
exercised by that component probe.

The [installed initial setup](../../experiments/m81/results/initial-setup.json)
retained stock NSS and enabled authselect fingerprint plus faillock together.
The independent disk and libvirt-managed TPM emulator have no host filesystem
shares or physical TPM passthrough. The original VM remained off throughout.
Test secrets and raw snapshots stayed guest-root private and were excluded from
exported evidence.

[Installed desktop and continuity evidence](../../experiments/m81/results/installed-desktop-and-continuity.json)
records actual RPM preparation, terminal CLI TPM enrollment, broker PIN,
KDE keyboard PIN/full-password UI, missing-module same-greeter password fallback,
and root recovery. After recovery and fresh enrollment, that same enrollment
survived the following maintenance without resealing or reenrollment:

- An actual ordinary `dnf upgrade --refresh -y` updated 26 packages and installed
  five new kernel RPMs. PAM,
  authselect and Plasma EVRs did not change in that available transaction;
  a separate actual `dnf reinstall -y pam authselect-libs` replaced seven native
  runtime inodes. Both retained the same usable TPM PIN.
- Native systemd-sysusers added an unrelated service account, and authselect
  regenerated its policy. Account bindings, credentials, LocalPIN throttles,
  native password tallies and owned policy bytes remained intact.
- Actual reboots preserved the same PIN. Compatible schema-2 RPM upgrades
  `.1 → .3 → .4` and `.5 → .6` automatically restored the previously tested
  active gate with identical enrollment and counters; an explicit downgrade
  was refused. The final build booted the
  [newly installed kernel](../../experiments/m81/results/kernel-boot.json)
  `7.2.11-200.fc44.x86_64`, retaining the same native PAM and graphical KDE PIN.
- A reboot during suspended package maintenance retained the disabled gate and
  exact state. Explicit resume restored the tested activation and same PIN.

The [update summary](../../experiments/m81/results/updates-summary.json)
identifies the individual transaction results stored alongside it. The
[disabled-fingerprint profile](../../experiments/m81/results/without-fingerprint-profile.json)
kept the native factor disabled, with no interactive authentication prompt or

postlogin. Policy checks refused them, existing PINs were denied, and native
restrictions retained their denial and failure history. Exact restoration and
genuine password success recovered the same enrollment without manual tally
resets. The final source suite and final RPM checks are recorded separately from
earlier build-specific component and lifecycle cases in the evidence files.

The final RPM also passed actual KDE PIN and full-password UI. Actual removal
restored both original KDE services, durably revoked account authority and
preserved native tallies; the restored stock KDE full-password UI then passed.

## Compatibility limits

The target is Fedora KDE 44 x86_64 local files accounts with enforcing SELinux,
stock local authselect semantics and the documented one-time persistent native
faillock setup. Unknown NSS/PAM providers, systemd-homed, custom required factors,
foreign shadow reserved-field use and incompatible native ABIs require explicit
compatibility work. Unknown factors preserve the native password/fingerprint
route while refusing PIN eligibility. Direct root editing or reconstruction of
account databases, including lock-respecting vipw/vigr, copying live markers or
restoring old account snapshots requires durable revocation and fresh identity
provisioning. Ordinary native record-preserving account tools remain supported.

No implementation can promise arbitrary future ABI or policy changes. Ordinary
compatible Fedora updates should retain enrollment; a changed security contract
must retain password recovery and refuse an unsupported PIN route. Physical
fingerprint devices, TPMs, alternate filesystems, power-loss behavior, an actual
AccountsService GUI/DBus administration run and the full physical desktop matrix
remain separate evidence. The tested filesystem was Fedora's default Btrfs.
This report does not claim a production release, hosted CI execution or
independent specialist review.
