# localpin-tpm (M4)

The ADR 0002 backend is a one-operation native worker primitive. It recreates and validates the RSA2048 owner primary, refuses provisioned owner authorization, derives the sealed object's authorization with shared RustCrypto Argon2id v19, and uses a fresh salted unbound HMAC session with AES128CFB parameter protection. Unseal encrypts its response without setting command decryption. It validates canonical public areas, recomputed SHA256 Names, exact templates and the protected account/generation record before authorization. Only the exact first-session TPM AUTH_FAIL becomes a PIN mismatch.

The payload is `LPT1`, version 1, Argon2id/v19 identifiers, account incarnation/generation, bounded KDF parameters, a 16-byte salt, parent public/Name, object public/Name and opaque private blob. It contains no authValue, independent PIN verifier or unsealed secret/hash. Protect the whole authoritative record with M3; arbitrary replacement of every protected field replaces the authoritative credential. Backend results require M3's durable completion and active-generation fence before authorization.

`NativeOperation` is consumed by enrollment, a trusted staged-record trial, or one `CredentialVerifier` call. A verifier cannot submit a second job. Every invocation creates one ESAPI context with at most one parent, child and session; only its owned handles are flushed. A match requires acknowledged explicit cleanup. Error paths retain context-drop fallback. KDF work requires the same non-cloneable aggregate M2 permit as software, and verification requires an already durable `VerificationJob`. Shared DA capability reads fail closed; with reserve two, an attempt is allowed only when `maximum - counter > 2`. Other TPM clients can race the read.

Native calls and cleanup can block. M5 must run these primitives in short-lived supervised processes, bound process/context slots, keep leases until actual reaping, close expired result channels and reject late results. The crate does not implement a production supervisor, deadline or broker. Sensitive Rust owners erase auth/unsealed data on drop. The pinned wrapper copies data through C input/output buffers and native stacks without a comprehensive native-memory-erasure guarantee; process disposal limits their lifetime. No result cache is retained.

Build requires pinned `tss-esapi 7.7.0` and matching TPM2-TSS `tss2-{sys,esys,tctildr,mu}` development libraries in `>=4.0.0,<5.0.0`; this milestone tests Fedora's exact 4.1.3 native build. Production construction selects `/dev/tpmrm0` explicitly and reads no environment TCTI. Unit tests never connect to it. The `simulator` feature adds an explicit localhost-only test transport.

Run ordinary parser/template/DA policy tests with `cargo test -p localpin-tpm`. The opt-in native suite needs `swtpm` and `tpm2-tools` and permission to bind disposable localhost TCP sockets:

```sh
python3 crates/localpin-tpm/tests/run_simulator.py
```

The runner gives the owned test process group a 120-second execution deadline, requests termination, bounds waiting for the direct Cargo child, and removes its private temporary state. Kernel I/O can delay descendant exit; this fixture does not establish production reaping guarantees. The suite starts only its own simulators, records synthetic wire traffic only in memory, checks salted sessions/parameter flags and an unprotected recorder control, correct/wrong/empty auth, empty-policy rejection, durable attempt capability composition, primary recreation, foreign-TPM copied blobs, same-TPM substitution, metadata corruption, DA reserve/lockout, unavailable transport and nonempty hierarchy refusal. Simulator-only tools configure only owned disposable TPM state. No test uses host `/dev/tpm*`, persistent handles or NV state. The real M3 integration test is in `localpin-storage`'s explicit `tpm-simulator-tests` feature. Independent TPM specialist review, hardware/resource-manager evidence and M5 supervision remain release gates.

Primary APIs reviewed: [tss-esapi 7.7 Context](https://docs.rs/tss-esapi/7.7.0/tss_esapi/struct.Context.html), [upstream pinned source](https://docs.rs/crate/tss-esapi/7.7.0/source/src/context.rs), and [ESAPI specification](https://trustedcomputinggroup.org/wp-content/uploads/TSS_ESAPI_v1p0_r14_pub10012021.pdf). The construction and transport trust assumptions remain those in ADR 0002.
